The problem

Every new project pays the same tax

Hours of AI and CI wiring, every time. Everyone does it a little differently, and it quietly rots the moment your standards move on.

Without WellForge

  • Agents, prompts and CLAUDE.md wired by hand, per repo
  • A spec workflow each team reinvents, or skips
  • Coverage and SAST thresholds copied in, then quietly lowered
  • CI pasted from the last project, bugs included
  • Day two: your standards move on, the scaffold doesn't

With WellForge

  • One interview, /wellforge:new, and the agent team is in
  • The same spec → plan → tasks flow in every repo
  • Gates referenced from one place and pinned, never copied
  • CI wired and green before the first feature
  • /wellforge:upgrade re-templates when presets evolve

Agent-ready from the first commit

The plugin is enabled in the repo itself, so every teammate who opens it gets the same agents, commands and hooks.

Gates you can't quietly lower

CI calls the central gate workflows at a pinned tag. Raising the bar is one PR for the whole fleet; lowering it locally isn't an option.

Upgradeable, not a snapshot

The manifest records the template and version that made the repo, so copier update can bring it forward when presets evolve.

What WellForge is

Six pillars, one command

Each one is a thing every team ends up building for itself. WellForge builds them once.

01 · Spec-driven

Spec-driven framework

A standardized spec → plan → tasks workflow, owned in-house so it encodes your conventions and doesn't churn under you.

02 · Agents

Multi-agent team

Product Owner, Architect, Designer, Frontend & Backend Devs, DevOps, Quality Engineer and Evaluator, each a subagent with a crisp role.

03 · Orchestrator

AI orchestrator

Routes work to the right agents, enforces the spec workflow, and coordinates handoffs from PO → Architect → Devs → QE.

04 · Scaffold

Scaffolder + connections

Recommends a stack, generates from a versioned template, and guides MCP/CLI connections to GitHub, CI, cloud, and observability.

05 · Gates

Quality gates as law

Coverage, lint, types, SAST, dependency and secret scans: defined centrally, enforced in CI and locally. Never left to individual discretion.

06 · Lifecycle

Upgradeable lifecycle

Every project records the template + version that made it, and can be re-templated when presets evolve. A scaffold that doesn't rot.

How a goal flows

One goal, a team of agents

/wellforge:orchestrate hands the work down the line. Each agent produces one artifact, and you approve at the gates that matter.

  1. Product Ownerspec.md
  2. Architectplan.md
  3. Designerdesign.md · UI only
  4. Frontend / Backend Devcode, test-first
  5. Quality Engineergates + verdict
  6. Evaluatoreval-report.md

A red QE verdict loops back to the devs, capped per feature, so a run always ends.

How it fits together

Three layers, because a plugin alone can't

Pillars 1–3 live in the AI session; pillars 4–6 need artifacts that outlive it: versioned templates and CI workflows. So WellForge is three cooperating layers.

wellforge-plugin/

Agent plugin

Skills, agents, commands, hooks, MCP: the spec workflow, the agent team, the orchestrator, and local gate enforcement.

Covers: pillars 1, 2, 3
copier.yml + templates/

Copier template

A monorepo template chosen for first-class copier update re-templating: the scaffolder and the upgradeable lifecycle.

Covers: pillars 4, 6
.github/workflows + gates/

Reusable CI gates

Central thresholds and SAST configs, referenced (not copied) by every scaffold, so raising the bar is one PR for the whole fleet.

Covers: pillar 5

Match ceremony to stakes

Rigor tiers

A throwaway prototype and a regulated production service shouldn't pay the same setup cost. Pick a tier per feature. Lower tiers defer rigor as tracked debt; they never lower the bar.

spikemvpproduction
Feasibility, may be thrown awayValidate with usersShip it and own it
Who buildsMain loop, from a one-paragraph briefPO → dev agents → light QEThe full agent team
Human gatesNone (review the result)Spec approvalSpec + plan
CoverageAdvisoryAdvisory80%, blocking
SAST (high)Not runBlockingBlocking
LM-judge evalOffOffThe gate into done

Graduate with /wellforge:promote, which pays the deferred debt; production only on an eval pass. A security floor, a secret scan over the full git history, blocks in every tier, alongside the linear-history and Conventional Commits checks.

One command per job

Playbooks for the whole lifecycle

Every stage of the SDLC has a WellForge entry point, from a blank folder to a shipped release.

Greenfield

Start a new project

One interview and you get a building, CI-gated repo with the agent team wired in.

/wellforge:new
# interview → stack pick → scaffold →
# build check → connections → first spec
Spec-driven

Add a new feature

The full spec → plan → tasks flow with a human gate at each step. A design stage kicks in for UI.

/wellforge:spec → :plan → :tasks → :implement → :done
# UI feature? add /wellforge:design after :plan
# shortcut, end-to-end:
/wellforge:orchestrate "add password reset"
Test-first

Fix a bug

QE reproduces it with the smallest failing test, a dev makes it green without weakening it, QE checks for regressions. Every fix names a root cause first; after three misses it questions the design instead of trying a fourth.

/wellforge:orchestrate "reset email never arrives"
# QE repro (failing test) → dev fix → QE verify
Scaffold · not a feature

Add a new service

A new service is scaffolding from a preset, not a spec-driven feature. New repo → :new. Inside a monorepo → ask the stack skill.

# standalone repo
/wellforge:new
# inside an existing monorepo (stack skill)
"scaffold a new Hono service: billing"
Existing code

Adopt a brownfield repo

Brings the workflow and calibrated gates to a project you already have. Additive only, one revertable commit.

/wellforge:adopt
# AI-readiness → gap-check vs presets →
# calibrated gates → release wiring
Before you build

Decide an idea

One question at a time, each with a recommendation, ending in a decision ledger that keeps what you decided apart from what you delegated.

/wellforge:grill-me "offline mode for field techs"
/wellforge:grill-me --docs  # + glossary & ADRs
/wellforge:spec --grill      # same interview, then the spec
Quality check

Evaluate an existing project

Score a feature against the rubric, or take the pulse of the whole repo.

/wellforge:eval    # LM-judge a feature vs rubric
/wellforge:status  # where each feature sits
/wellforge:triage  # which specs are rotting
/wellforge:doctor  # tools, MCP, hooks, guards
Feasibility

Spike a question

The fast lane: build from a one-paragraph brief, advisory gates, no agents, no approval. May be thrown away.

/wellforge:spike "stream LLM tokens over SSE?"
# raise it later with /wellforge:promote
Keep it healthy

Improve what you work in

Look back for what slowed a session down, and scan for modules that make every change expensive. Both propose from evidence and change nothing without your yes.

/wellforge:retro  # fixes to the environment, ranked
/wellforge:improve-architecture
# shallow modules → refactor candidates
Lifecycle

Ship & maintain

Cut releases from Conventional Commits, and keep scaffolds from rotting as presets evolve.

/wellforge:release  # bump + CHANGELOG + tag
/wellforge:upgrade  # re-template (copier update)
/wellforge:promote  # graduate a rigor tier
# add --dry-run: plan only, changes nothing

Iterating? Re-run the command. Agent commands are one-shot, not a mode. /wellforge:orchestrate and :implement drive the agent loop (QE → dev → QE) for that single invocation; plain follow-up messages only steer the main loop. To keep the team working after a partial fix, re-invoke with what's still broken:

/wellforge:orchestrate "the reset fix is incomplete: it works
for email users but SSO users still get no token"

Not sure which fits? /wellforge:orchestrate classifies any goal (feature, bugfix, refactor or infra) and runs the matching pipeline.

Get started

From nothing to building

macOS or Linux, GitHub, and one of Claude Code, OpenCode, or GitHub Copilot (VS Code, via adapter).

1

Install and set up

brew install the WellForge CLI, then wellforge setup checks the toolchain, clones the repo and installs the plugin with its agents, commands and skills.

2

Run the front door

/wellforge:new interviews you, recommends a stack, generates the scaffold, verifies the build, and walks the connections.

3

Or adopt an existing repo

/wellforge:adopt brings the workflow and calibrated gates to a brownfield project, one layer at a time, additive only.

4

Build with the team

/wellforge:orchestrate drives the full agent pipeline on a goal: spec → plan → tasks → code → QE → eval.

# install
brew tap matteocodogno/wellforge https://github.com/matteocodogno/wellforge
brew install matteocodogno/wellforge/wellforge
wellforge setup
# …or manually, inside Claude Code
/plugin marketplace add matteocodogno/wellforge
/plugin install wellforge

# then scaffold a new project, or adopt one
/wellforge:new
/wellforge:adopt
